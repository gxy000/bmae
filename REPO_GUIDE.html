1. What this repository does

The repository contains encoder pretraining, supervised finetuning, and whole-volume evaluation for two tasks. The encoder learns features from image patches; the downstream prediction head converts those features into task-specific outputs.

Cell detection · celldet

Find cell centers

The model predicts a center heatmap and spatial offsets. Evaluation decodes these into cell coordinates and matches them to annotated centers.

Evaluator:
test_evaluate_cn_wholev.py

Neurite segmentation · axonseg

Recover neurites and separate instances

The model predicts a heatmap and instance embeddings. Evaluation assembles volume predictions and measures centerline, instance, and connectivity quality.

Evaluator:
test_axonseg_multidata_wholev.py

PretrainUnlabeled image crops → encoder weights
→
FinetuneLabeled data + encoder → task checkpoint
→
EvaluateCheckpoint + test volumes → metrics and figures

MAE learns by reconstructing masked image patches. DINO learns features through a student–teacher objective using multiple crops. Both are pretraining options; finetuning adds the supervised task.

These stages are separate commands. Choose the encoder checkpoint explicitly with --finetune; use --resume to continue a training run. Omitting --finetune starts downstream training from scratch.

4. Set up your environment

Start with the original MAE installation notes. MAE refers to the DeiT setup and uses timm==0.3.2, including an import compatibility fix for newer PyTorch versions. This supplies the background for the encoder code. Brain MAE also needs 3D image readers, morphology libraries, and evaluation packages.

For this repository, use the following commands from your checkout. The dependency pins were checked against the lab’s working mae_viz environment. They create a separate environment named brain-mae.

conda env create -f environment.yml
conda activate brain-mae
bash draft/setup_environment.sh

5. Your first session

  1. Run the small CPU checks. These require no production images or weights. 
    MPLBACKEND=Agg python -B -m unittest discover -s tests -v

    The reviewed version passes 20 tests. This checks core code paths; it does not validate a full distributed GPU experiment.

  2. Read one launcher and inspect its options. 
    python main_finetune_hm_offset.py --help
python test_evaluate_cn_wholev.py --help

    Identify the image root, manifest, architecture, checkpoint, GPU selection, and output directory.

  3. Evaluate a supplied checkpoint. Once its images and weights are available: 
    bash draft/eval_scripts/eval_celldet_egfp_4x.sh

    This launcher compares two cell checkpoints. The neurite launchers are listed below; some run more than one dataset. Open the result JSON and inspect prediction figures alongside the numerical scores.

Typical model aliases are mae_vit_base_patch16_4 for cell finetuning and mae_vit_base_patch16_1c_32 for neurites. The neurite MAE example uses --vol_size 32 for 32 × 256 × 256 crops on copied EGFP images. It is an exploration example; the original neurite finetuning run uses a separately supplied NeuN/GFAP encoder checkpoint.

A good first experiment

Record an evaluation baseline, duplicate its launcher, and vary one heatmap threshold (--threshold_hm for cells; --hm_threshold for neurites). Compare false positives, missed structures, and visual predictions. Keep the checkpoint, test split, matching settings, and other parameters fixed.

For training experiments, give each run a new --output_dir and --log_dir. Keep a copy of the exact command. Effective batch size is batch_size × accum_iter × number of GPUs; changing GPU count can also change random sampling and results. Training launchers enable W&B logging; adjust their logging flags to your lab account or omit the W&B flags.
